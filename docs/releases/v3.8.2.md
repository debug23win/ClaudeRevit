# v3.8.2 — responsive chat during scripts

The docked chat shared Revit's API/UI thread, so a long synchronous script blocked
typing, progress and Stop until it returned.

- Add **General → Chat interface**: separate window (default/recommended) or the
  original docked pane. Save and restart Revit to apply the choice.
- Run the separate chat on its own STA/input queue. Drafts, attachments, live
  supplements, Copy log and Stop remain available while the host API thread is
  occupied. Project/workspace snapshots are published atomically and marshalled
  to the chat dispatcher.
- Compile direct `execute_csharp` and `validate_csharp` calls on workers. Retain
  prepared bytes for the queued execution and record compilation time separately.
- Insert cooperative cancellation checks into C# loop bodies, preserving compiler
  line numbers. Stop can roll back the current managed transaction at the next
  check. Individual native API calls must finish first; Python/Dynamo and code
  suppressing cancellation do not gain automatic C# loop checks.
- Deliver script progress to API and MCP chats and throttle repetitive updates.

[Mode selection and cancellation limits](../chat-interface.md).

Validation: 183 unit tests, including emitted loop/cancellation/diagnostic tests;
isolated WPF regression with a deliberately blocked host thread; scoped HTTP MCP
and subscription CLI checks; builds for Revit 2025/2026/2027. Native Revit modelling
was not run by these tests.
