# v3.8.3

Bridge and component modelling can now reuse loaded native steel connections,
geometry-driving parametric sections and persistent keyed assemblies instead of
repeated one-off scripts. Steel/timber specifications remain live model schedules.

- Nine new tools (232 total): structural capability inspection, global truss layout,
  node create/update/read/validation, parametric section generation and SPDS profile,
  schedule and live-table authoring.
- Native structural connections are preferred in agent instructions. Missing compatible
  resources and unresolved modelling/documentation choices must be clarified first.
- Rectangular/box/I family sections have constrained geometry, formulas and independent
  flex/volume checks. `flex_family` can reject parameters that do not change geometry.
- Type changes restore compatible instance values, verify regeneration and report
  replacement IDs. Keyed node updates preserve identities, support face/local placement
  and preview declared solid/interface checks in one Undo operation.
- Live native SPDS steel/timber schedules, exact profile widths, grouping and totals.
  Derived mass matrices update model parameters on source edits/additions/deletions.
  Invalid inputs visibly mark incomplete tables. Required updater warns if missing.
- Code execution is always enabled; no permission checkbox or persisted opt-out.
  Legacy code-group settings cannot block scripts/custom tools.
- Worker compilation/validation duration and failure reasons appear in the task journal;
  JSON results safely serialize Revit element/vector/transform/bounding-box snapshots.

See [workflows, examples and limits](../structural-workflows.md). Engineering design,
fully verified bore geometry, automatic refresh of custom node geometry and whole-set
SPDS compliance are not claimed. Native Revit family/node/schedule acceptance tests
remain necessary; automated CI validates logic, transports, interface and compilation.
