# v3.8.6 — review fixes: silent no-ops, broken conversations, code-execution switch

Fixes from a code review of everything merged since v3.4 (both reviews merged and every finding re-checked against the code). Nothing here was exercised in Revit yet; the pure-logic parts are covered by new unit tests.

**Wrong results without an error**
- `change_element_type` (and node part type changes) restored the instance's own "Type" / "Family and Type" parameters after the swap, putting the old type back while reporting success. Type-identity parameters are no longer "preserved", and the call fails if the element is still on its old type.
- `execute_csharp` serialized the script's return value inside the transaction: a Curve, Parameter or Document in the result threw and rolled back work that had succeeded. Serialization can no longer fail the call (cycles ignored, ToString fallback), and it no longer pins the script's assembly in memory.
- `set_parameter` stopped at the first group with a name match, so a material named like a type was never found. Groups are now searched until the parameter actually accepts a candidate, materials first for material parameters.
- The live SPDS updater could throw inside the user's own edit, making Revit cancel it or disable the updater. It no longer throws, and costs nothing in projects without live tables.

**Conversations that broke for good**
- An image from `export_image` / `read_attachment` was inserted between tool results, a 400 on the next request — saved into history, so every later request failed. Images now follow all tool results, histories saved in the old order are repaired when sent, alt (text-only) providers get no image parts, and images over ~1 MB stay on disk instead of riding in every request.
- With no project open, every chat message failed with "The bound document was closed" and stayed in history to be replayed.

**Code execution (C#, Python, custom tools)**
- On by default, and now switchable off in Settings → General → *Allow Claude to run code*. Off means neither the chat nor any MCP client holding the token can run code. Earlier saved opt-outs from the opt-in era are ignored.

**MCP / CLI**
- Codex abandoned tool calls after 120 s while Revit allows 10 minutes, so long calls committed after the model was told they failed. Aligned.
- A sign-in check (`claude auth status` / `codex login status`) ran before every message; it is now cached, and a slow check no longer shows up as "Cancelled".
- Mojibake (`вЂ”`) in the MCP instructions and tool index; tool index never refreshed after background-loaded or newly saved tools; driving rules sent to Claude Code twice; a user supplement lost when the client cancelled a call; a model request for an alias (`opus`) never satisfied, padding every tool result; Codex's recoverable `error` events failing completed turns.
- The stdio bridge re-initializes a session the server forgot instead of failing until restart, and answers requests over 2 MB instead of silently dropping them.

**Other**
- `run_bimstarter_command` was not protected against running in a different tab than its bound document.
- PNG exports over 5 MB are reported as exported (with a note) instead of failing after the file was written.
- `execute_csharp` snippets naming `Units` compile again.
- Alt providers: streamed tool names are reassembled correctly in all three streaming styles.
- No more full-model snapshot on the UI thread for the task journal; per-element journaling is bounded again.
- Chat sessions of closed documents are released; attachment copies unused for 30 days are removed at startup; usage lookup handles Codex's local-date folders; family upgrade warnings are no longer processed twice; the benchmark cleanup timeout now applies.
- Help and README no longer promise one Ctrl+Z per prompt: each tool call (or batch, or script) is one undo step.

235 unit tests pass; builds for Revit 2025, 2026 and 2027.
