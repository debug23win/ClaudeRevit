# v3.10.0 — Benchmark diagnostics and agent controls

## Detailed benchmark logs

- Each benchmark run writes an immediately flushed JSONL file to `%APPDATA%\ClaudeRevit\benchmarks\<run_id>.jsonl`.
- Events include modeller/judge selections, task prompts and criteria, limits, status transitions, model probes before and after execution, objective checks, modeller messages, judge requests and raw responses, verdicts and scores.
- Tool events record inputs, results, model changes, queue/execution timings and errors; script compilation starts are recorded before worker execution.
- Cancellation, exceptions with stack traces and scratch-copy cleanup are logged. A partial final record can be retried when reading a live log.
- The benchmark window displays the log path. Result rows link scores to the exact run ID and log file.
- Per-run files are retained without the rolling task journal's truncation. They contain model data and generated text: review before sharing and remove old files when no longer needed.

## Agent access

- `plugin_settings` reads and updates supported non-secret preferences, and reads/saves independent Codex and Claude Code model/effort selections. API keys, MCP tokens, executable paths and endpoint URLs are excluded.
- `benchmark_control` lists tasks, starts selected tasks asynchronously, reports status, requests cancellation, lists run files and reads diagnostics in pages.
- Agent-started runs use fresh disposable copies of a saved, unmodified local scratch RVT/RFA. Modeller and judge selections are independent; defaults are Codex, 24 rounds and 300 seconds per task.
- Settings changes are blocked while a benchmark is running or queued. The benchmark modeller cannot start or stop its own run.
- Chat and MCP driving instructions describe how to discover the new tools.

See [benchmark usage and tool argument examples](../benchmark.md#detailed-file-diagnostics-and-agent-controls).
