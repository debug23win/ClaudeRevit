# v3.8.7 — readable input errors in every tool

Every tool now reads its required inputs through checked readers (`ToolInput.Required*`) instead of `input["x"].GetDouble()` and friends — 382 call sites in 160 tool files.

Before, a model that left out a parameter, sent one id where a list was expected, or wrote a word where a number belongs got an error that named nothing: "Object reference not set to an instance of an object", "The given key was not present", "The requested operation requires an element of type 'Number'". It then guessed and spent a round, often repeating the same mistake. Now the error says which parameter, what was expected and what arrived, and it is returned as an ordinary failed result the model can act on.

Behaviour otherwise stays the same, with two deliberate changes:
- a number sent as a string (`"3000"`) is accepted;
- an integer parameter given a fraction (`2.5` for a count) is rejected instead of being rounded; whole values written as `3.0` are accepted.

A string parameter sent as JSON `null` still reads as "not given", exactly as before.

242 unit tests (7 new for the readers), MCP and subscription CLI checks pass; builds for Revit 2025, 2026 and 2027. Not exercised in Revit.
