# Claude Revit

Агенты MCP: выберите **Claude Code · MCP** или **Codex · MCP**, затем модель и
глубину рассуждений. Настройки агентов сохраняются отдельно; Codex получает
список моделей из установленного CLI. [Выбор агента и настройка](docs/openai-codex.md).

**v3.7:** анализ вложенности и flex-проверки семейств, нативные параметрические формы,
сложное армирование, операции с контролируемым preview, каталог 63 команд BIMStarter,
ФОП ADSK 2019/2021 и профиль EIR «Самолёт». Бенчмарк по умолчанию работает через
подписку Codex/ChatGPT; модели исполнителя и судьи выбираются независимо.
[Новые инструменты и ограничения](docs/advanced-bim.md) · [Разбор EIR](docs/samolet-eir.md).

[English](README.md) | **Русский**

Claude AI внутри Autodesk Revit — закрепляемая панель чата со **213 инструментами**, через которые Claude напрямую читает и изменяет вашу модель. Попросите его построить стены, создать спецификации, расставить семейства, образмерить оси, заармировать конструкции, собрать параметрическое семейство, оформить листы — и он сделает это сам. Работает на **Revit 2025, 2026 и 2027**.

Запускать можно на потокенном **Anthropic API**, на вашей **подписке Claude Pro/Max** (через встроенный MCP-сервер + Claude Code CLI — ноль расходов на API) или на любом **OpenAI-совместимом** провайдере (DeepSeek, Gemini, OpenRouter, Groq, локальные Ollama…).

## Возможности

- **Сложные семейства** — рекурсивный анализ, проверка типов/размеров/вариантов с откатом, пять видов нативных форм, void-комбинации, общие параметры из ФОП и связи вложенных экземпляров.
- **Нативное армирование** — контуры с линиями/дугами, хомуты/отгибы, раскладки, free-form стержни, ограничения по реальным кандидатам, муфты и PNG-эскизы для спецификаций.
- **Точные операции** — размеры по стабильным ссылкам, полный preview каскада удаления, количества материалов с отдельной окраской, балочные системы и раскраска по параметру с данными легенды.
- **BIMStarter** — каталог всех 63 команд исходного снимка с честным покрытием, независимые нативные операции и вызов кнопки совместимой установленной версии плагина. Диалоговые/облачные команды требуют самого плагина и действий пользователя.

- **Закрепляемая панель чата** в Revit с потоковым выводом ответов
- **Отдельная история каждого проекта** — сообщения и сессии Claude Code/Codex следуют за активным документом. Несколько экземпляров Revit получают отдельные слоты истории. При ручном переключении документа текущая задача останавливается до загрузки другого диалога.
- **Независимые MCP-клиенты** — сведения о модели, команды из настроек и отмена запросов относятся к конкретному соединению. В настройках можно выбрать подключённый клиент. Кнопка остановки отменяет его очередь и ждёт завершения или отката уже выполняемой операции Revit.
- **BIMStarter, ADSK и EIR** — живые GUID, привязки, единицы, шаблоны и спецификации через `get_project_standards`; 313 GUID BIMStarter и 323 GUID ADSK (566 уникальных вместе; 1120 строк с редакциями/переводами) через `get_shared_parameter_catalog`. `get_standard_workflows` объясняет правила подсчёта и различия профилей; `validate_project_standard` выполняет частичный аудит EIR «Самолёт». Рекомендованные группы из XLSX не заменяют живые привязки.
- **213 инструментов**: моделирование, виды, листы, аннотации, спецификации, фильтры, семейства, редактор семейств, армирование
- **Несколько провайдеров ИИ** — Claude (Opus 5 / Fable 5.1 / Sonnet 5 / Opus 4.8 / Fable 5 / Haiku 4.5, + Sonnet 4.6 / Opus 4.7) **или** любой OpenAI-совместимый эндпоинт: OpenAI (пресеты GPT-6 Astra и GPT-5.6 Sol/Terra/Luna), DeepSeek, Google Gemini, Qwen, OpenRouter, Groq, локальные **Ollama** / **LM Studio**. Выберите «Alt» в списке моделей; бесплатным и локальным моделям ключ Anthropic не нужен.
- **Режим Auto (экономный)** — по умолчанию: дешёвая модель (Sonnet 5) ведёт весь ход и советуется с сильным advisor'ом (Opus 4.8 или Fable 5) только когда нужен план — через advisor-tool Anthropic. Кэш дешёвой модели остаётся горячим всю сессию, advisor оплачивается лишь за короткий совет. Старый режим (переключение всего хода на Opus) доступен в настройках.
- **Режим подписки (MCP)** — выберите Claude Code · MCP или Codex · MCP, затем модель и глубину рассуждений. Работа идёт через официальный CLI и локальные инструменты Revit; настройки и сессии агентов сохраняются отдельно.
- **Бенчмарк моделей (📊)** — по умолчанию Codex по подписке ChatGPT для исполнителя и судьи. Для каждого независимо выбираются агент, доступная модель и глубина рассуждений; API выбирается явно. Проверка подписочного входа исключает унаследованные API-ключи. Судья работает без инструментов и оценивает объективные данные до/после; ошибка судьи означает «без оценки». Очистка добавлений сначала проверяет каскад удаления и защищает существовавшие элементы; правки и удаления старых элементов она не восстанавливает. [Проверки и ограничения](docs/advanced-bim.md#benchmark).
- **Ленивая загрузка инструментов** — в каждый запрос едет лишь базовый набор; специализированные группы (арматура, инженерка, спецификации, листы, аннотации, разрезы, редактор семейств, экспорт) раскрываются по требованию через `find_tools`, что срезает «налог на каталог инструментов» примерно на ⅔ (особенно заметно на альт-моделях без кэша). `run_batch` повторяет один инструмент по многим элементам за один ход, каждый элемент — в своей вложенной транзакции: сбойный элемент откатывается сам по себе и не оставляет половину правок. Инструменты, поставленные вами под диалог подтверждения, он не заворачивает — их по-прежнему спрашивают поштучно.
- **Оформление и контроль качества** — рутина, которая обычно требует разового скрипта: `autonumber_elements` (нумерация в порядке чтения чертежа: строки разбиваются по допуску, поэтому кривоватая сетка всё равно читается слева направо), `derive_parameters` (заполнение параметра из геометрии/свойств или по шаблону `{placeholder}`), `auto_join_geometry` (находит пересекающиеся пары и соединяет — лечит двойной подсчёт бетона), `calculate_weight` (масса по реальному объёму × плотность материала; арматура — по длине × номинальный диаметр), `get_element_hosts`, `diagnose_model` (предупреждения, формы на месте, взорванный DWG, огромные группы — с рекомендацией по каждой находке), `clean_model` (удаляет их; **по умолчанию только показывает**), `assign_worksets`, `generate_sheet_set`, `batch_export_sheets`, `create_assembly`, `export_element_coordinates` (точки выноса в **общих координатах площадки**) и `query_linked_elements` (читает связанные модели, приводя координаты в систему хоста).
- **Данные для гибки арматуры** — `get_rebar_shape_sketch` возвращает длины прямых участков и углы гибов, группирует одинаковые стержни в позиции спецификации и умеет отдавать SVG-эскиз каждой формы.
- **Работает с MCP-клиентами не на Claude** — сервер определяет подключившегося клиента и отдаёт ему переносимую схему инструментов. Валидатор функций OpenAI отвергает ключевые слова ограничений, которые используются во всех этих инструментах (`minimum`/`maximum`, `minItems`, `oneOf`), и бракует такой список **целиком**, поэтому ограничения не выбрасываются, а переносятся в описание параметра. Claude-клиенты получают прежние подробные схемы. *(Если подключать модель OpenAI к серверу самостоятельно, а не через Codex, учтите: MCP у них работает через Responses API, а не chat completions.)*
- **Модели OpenAI тоже управляют Revit (через MCP)** — локальный **Codex CLI** подключается к тому же MCP-серверу, и GPT-6 Astra / GPT-5.6 Sol-Terra-Luna правят модель через инструменты Revit. Облачный ChatGPT до `127.0.0.1` не достучится, а выставлять сервер наружу — значит защитить правку модели одним токеном; Codex работает на вашей машине, туннель не нужен. Следующие сообщения продолжают тот же диалог Codex, сессия переживает перезапуск Revit.
- **Видно, кто управляет** — ответы сохраняют имя своего агента. Для внешнего MCP-клиента настройки показывают клиента из хендшейка и модель, сообщённую самим клиентом; это сообщение может быть неточным.
- **Проверка обновлений** — в панели появляется кликабельная ссылка «доступно обновление» (и кнопка «Check for updates» в Settings → About), когда на GitHub вышел релиз новее; только уведомление — загруженный плагин не может подменить свою DLL, пока Revit работает
- **Настройки по вкладкам** — General · Models · Subscription (MCP) · Tools · About
- **Одна отмена на запрос** — Ctrl+Z откатывает всё, что Claude сделал за один ход
- **Понимает выделение** — зелёная плашка показывает, что выделено; Claude знает, что значит «это»
- **Markdown** и **выделяемый текст** в сообщениях
- **Кликабельные ID элементов** — клик по ID в результате инструмента выделяет и показывает элемент в модели
- **Учёт стоимости и баланса** с кэшированием промпта (TTL 1 час на системный промпт и инструменты — каждый ход оплачивает только новые токены); введите свой баланс, и панель покажет остаток
- **Полная память контекста** — вся история диалога (вызовы инструментов, результаты, ID элементов) переживает перезапуск Revit: Claude помнит, что он построил
- **Автокомпакция** — при превышении контекстного бюджета модели старые ходы сжимаются в резюме, не переполняя окно
- **Старение результатов инструментов** — старые результаты усекаются на месте (и архивируются) ради экономии токенов; `get_full_result` достаёт полный результат по запросу
- **Локальное обучение** — `save_memory` хранит ваши предпочтения и стандарты проекта; каждый запуск кода журналируется вместе с изменениями модели, приёмы попадают в системный промпт с ранжированием по доле реальных успехов (приём, который чаще проваливается, отбрасывается, а не выдаётся за проверенный) и **переживают очистку чата**, а при закрытии Revit (или по команде `generate_diagnostic_report`) формируется диагностический отчёт о повторяющихся скриптах — чтобы превратить их в отдельные инструменты
- **Доступ ко всему Revit API (по согласию)** — когда готового инструмента нет, Claude может выполнить код: `execute_csharp` (по умолчанию — компилируемый C# в управляемой транзакции), `run_python` (Python прямо в процессе Revit через движок pyRevit / RevitPythonShell — без загрузки Dynamo, запускается мгновенно) или `run_dynamo_python` (движок Python из Dynamo, для проверенных фрагментов сообщества). **По умолчанию выключено**: включается галочкой в настройках.
- **Revit не подвисает** — потоковый ответ перерисовывается по короткому таймеру, а не на каждом токене (перестроение всего документа на токен квадратично по длине ответа, и всё это в UI-потоке Revit), а обычные вызовы инструментов одного раунда уходят на исполнение пачкой, а не по одному циклу Idling каждый. Отмена хода теперь снимает и те инструменты, что стояли в очереди, — после «стоп» модель не правится дальше.
- **Настраиваемый лимит вызовов** — сколько раундов инструментов Claude может сделать на одно сообщение (по умолчанию 24), поднимается в настройках для длинных автоматических задач
- **Подтверждение опасных операций (опция)** — по умолчанию выключено (обычные API-операции группируются для отмены); при желании включается диалог «Разрешить/Запретить»
- **API-ключ вводится в панели** (шестерёнка) и хранится зашифрованным (Windows DPAPI) — без открытых переменных окружения

## Установка (для пользователей)

Понадобятся:

- **Autodesk Revit 2025, 2026 или 2027** — установщик определяет, какие из них у вас стоят, и даёт отметить нужные галочками
- **Windows** (Revit работает только на Windows)
- **API-ключ Anthropic** — получите на [console.anthropic.com](https://console.anthropic.com/settings/keys) и пополните баланс в **Billing** — *или* бесплатный/альтернативный провайдер (DeepSeek, Gemini, OpenRouter, Groq, локальные Ollama / LM Studio…), настраивается в разделе Settings

Любой из двух способов:

### Вариант А — установщик .exe (проще всего)

Скачайте **`ClaudeRevit-Setup-vX.Y.exe`** из [последнего релиза](https://github.com/debug23win/ClaudeRevit/releases/latest), запустите, отметьте нужные версии Revit → Install. Готово.

> Windows SmartScreen при первом запуске может показать «Windows защитила ваш компьютер» (установщик пока не подписан). Нажмите **Подробнее → Выполнить в любом случае**.

### Вариант Б — одна команда PowerShell

```powershell
iwr https://raw.githubusercontent.com/debug23win/ClaudeRevit/main/install.ps1 | iex
```

В обоих случаях: запустите Revit, откройте любой проект и найдите вкладку **Claude** в ленте. Кнопка **Chat** открывает панель справа. При первом запуске нажмите **⚙** и вставьте API-ключ (или настройте альтернативного провайдера).

Для обновления просто повторите установку — подтянется последний релиз.

## Работа через подписку Claude (MCP)

Вместо оплаты по токенам через Anthropic API можно рулить Revit на вашей **подписке Claude
Pro/Max**. Плагин поднимает локальный **MCP-сервер** с инструментами Revit, а **Claude Code CLI**
к нему подключается и выполняет работу — расходы идут на подписку, а не на API.

1. **Установите Claude Code CLI** (консольная программа, это не приложение Claude Desktop).
   В PowerShell:
   ```powershell
   irm https://claude.ai/install.ps1 | iex
   ```
   Затем запустите `claude` и войдите своей подпиской. (Нужен VPN, если `claude.ai` недоступен
   в вашем регионе — и на установку, и на каждый прогон.)
2. **Включите MCP-сервер** в Settings → MCP (можно задать порт; путь к `claude` плагин находит
   сам, иначе впишите его вручную).
3. **В чате** выберите **Claude Code · MCP**, затем модель и глубину рассуждений. «Автоматически» использует модель CLI по умолчанию.

MCP-сервер можно также подключить к приложению **Claude Desktop** (или любому MCP-клиенту) —
готовый конфиг показан в Settings → MCP.

> Важно: связка Auto (advisor, авто-переключение haiku→opus) работает только на API и **не**
> действует в режиме подписки — Claude Code ведёт свой цикл одной выбранной моделью.

## Управление Revit моделями OpenAI (Codex)

Установите Codex и войдите через ChatGPT. В панели выберите **Codex · MCP**,
обновите список моделей и выберите модель и глубину рассуждений. Соединение MCP
настраивается автоматически для каждого процесса; API-ключ и ручная регистрация
сервера для панели не нужны. Настройки Codex сохраняются отдельно от Claude Code.

Для внешнего Codex-клиента в пакеты включены `revit-mcp-bridge.ps1` и
`revit-mcp-bridge.cs`; при копировании моста сохраняйте оба файла в одной папке.
[Подробная настройка и проверки](docs/openai-codex.md).

## Сборка из исходников (для разработчиков)

Понадобятся:

- **Visual Studio 2026 Community** (или Rider, или VS Code с C# Dev Kit)
- **.NET 8 SDK** и **.NET 10 SDK** — 2025/2026 собираются под .NET 8, 2027 — под .NET 10
- **Autodesk Revit** локально (нужен только для отладки по F5 — компиляция работает и без него)

Шаги:

1. Клонировать:
   ```powershell
   git clone https://github.com/debug23win/ClaudeRevit.git
   cd ClaudeRevit
   ```
2. Открыть `ClaudeRevit.sln` в Visual Studio.
3. ПКМ по проекту → **Restore NuGet Packages**.
4. Назначить `ClaudeRevit` стартовым проектом.
5. Нажать **F5**.

Пост-сборочный шаг сам копирует DLL и манифест в `%AppData%\Autodesk\Revit\Addins\<год>\`. F5 запускает Revit с подключённым отладчиком.

### Как устроена сборка

- Ссылки на Revit API берутся из NuGet-пакетов **Nice3point.Revit.Api.RevitAPI** и **RevitAPIUI** — локальный Revit для компиляции не нужен.
- Пост-сборочный таргет `DeployToRevit` копирует в `%AppData%\Autodesk\Revit\Addins\<год>\`. Чтобы пропустить (например, на CI): `-p:SkipDeploy=true`.
- Отдельный таргет `PackageRelease` складывает артефакты релиза в `bin\Release\release\` — его использует GitHub Actions.

## Версии Revit

Плагин поддерживает **Revit 2025, 2026 и 2027** и собирает отдельную сборку для каждой,
потому что версии работают на разных рантаймах .NET (2025/2026 → .NET 8, 2027 → .NET 10).
При установке обнаруженные версии уже отмечены; отметьте нужные, и каждая получит свою
сборку в отдельной папке `%AppData%\Autodesk\Revit\Addins\<год>\`.

Собрать локально под конкретную версию — параметром `RevitVersion`:

```powershell
dotnet build ClaudeRevit\ClaudeRevit.csproj -c Release -p:RevitVersion=2026
```

Пакет Nice3point (`$(RevitVersion).0.*`), целевой фреймворк и папка деплоя следуют за этим
одним значением. Различия API между версиями закрыты символами компиляции
`REVIT2025` / `REVIT2026` / `REVIT2027`. Revit 2024 и раньше работают на .NET Framework 4.8
и в текущую сборку не входят.

## Выпуск новой версии

Workflow `.github/workflows/release.yml` собирает все три версии Revit и публикует релиз.
Запустите его на вкладке Actions (**Run workflow** → введите версию, например `v1.30`) или
запушьте тег `v*`. GitHub Actions:

1. Собирает каждую версию Revit (2025/2026/2027) в Release с `SkipDeploy=true`
2. Делает zip на каждую версию (`ClaudeRevit-vX.Y-Revit<год>.zip`)
3. Компилирует установщик Inno Setup, объединяющий все три, со страницей выбора версий
4. Публикует GitHub Release с установщиком и zip-архивами

Пользователи получают новую версию тем же установщиком / командой `install.ps1`.

## Инструменты

Плагин даёт Claude **213 инструментов** по категориям:

- **Чтение модели** — элементы, параметры, уровни, материалы, стадии, семейства, информация о проекте, предупреждения, пакетное чтение позиций и габаритов (мм)
- **Создание геометрии** — стены, перекрытия, крыши, помещения, уровни, оси, двери, окна, колонны, балки, фундаменты, MEP (воздуховоды/трубы), топография, витражи
- **Армирование** — ряды стержней (с количеством и шагом), площадное и по траектории, защитные слои, список типов, инспекция существующего армирования, данные для гибки (длины участков, углы гибов, позиции спецификации, SVG-эскизы форм)
- **Оформление и контроль качества** — пространственная автонумерация, заполнение параметров по правилам, массовое соединение/разъединение геометрии, навигация хост ↔ размещённые, подсчёт массы по плотности материала, генерация комплекта чертежей (вид + лист на этаж), пакетный экспорт PDF/DWG с шаблоном имени файла, сборки с видами для КМД
- **Здоровье модели** — `diagnose_model` (предупреждения по типам, формы на месте, взорванные CAD-импорты, неразмещённые помещения, огромные группы, варианты, виды без шаблонов — с уровнем важности и рекомендацией) и `clean_model` для их удаления, по умолчанию в режиме проверки
- **Совместная работа** — назначение рабочих наборов по правилу и чтение элементов из связанных моделей в координатах хоста
- **Вынос в натуру** — координаты элементов в общей или внутренней системе, порядок N/E, естественная сортировка марок, выгрузка в CSV
- **Редактор семейств** — нативная сборка параметрических семейств: список/добавление/удаление параметров, формулы, значения (мм), переключение экземпляр/тип, привязка параметров вложенных элементов, линейные массивы с параметрическим количеством, образмеривание между ссылками с меткой-параметром
- **Обучение и запасной выход** — `save_memory`, `get_script_journal`, `generate_diagnostic_report`; `execute_csharp` / `run_python` / `run_dynamo_python` (код для действий, не покрытых инструментами — по умолчанию выключено, включается галочкой)
- **Операции с элементами** — перемещение, поворот, копирование, зеркало, массив, удаление, параметры, закрепление, соединение/разъединение
- **Виды** — 3D, планы, разрезы, фасады, фрагменты, дублирование, зависимые виды, масштаб, шаблоны, подрезка/секущий бокс
- **Листы** — создание листов, размещение видов и спецификаций, перемещение видовых экранов
- **Спецификации** — настоящие ViewSchedule с выбором полей, экспорт CSV
- **Аннотации** — размеры, марки, текст, линии детализации, штриховки, опорные плоскости, ревизии, высотные отметки
- **Видимость** — скрыть/изолировать, цветовые переопределения, видимость категорий, фильтры
- **Интерактив** — `pick_point_in_view` для сценариев «кликни, куда поставить»
- **Семейства** — загрузка .rfa, список загруженных, размещение экземпляров, дублирование/правка типов
- **Группы** — создание, размещение, разгруппировка
- **Экспорт** — изображения видов, PDF, DWG, CSV спецификаций, сохранение документа
- **Выделение** — `select_similar` («выделить все экземпляры этого типа»)

Реализации и вспомогательные классы — в папке [`ClaudeRevit/Tools/`](ClaudeRevit/Tools). Некоторые файлы содержат несколько связанных инструментов; точный список регистраций находится в [`App.cs`](ClaudeRevit/App.cs).

## Архитектура

- **`App.cs`** — точка входа `IExternalApplication`: регистрирует инструменты, панель, кнопку в ленте и хук обучения DocumentChanged
- **`Tools/`** — классы `IRevitTool`. Новый файл + строка регистрации в `App.cs` → инструмент доступен Claude
- **`Tools/ToolDispatcher.cs`** — `IExternalEventHandler`: исполняет вызовы в API-потоке Revit; каждый инструмент — в `Transaction`, обычные API-операции группируются в `TransactionGroup`; family/preview-инструменты закрывают группу и управляют собственными транзакциями
- **`Services/ChatService.cs`** — агентский цикл, независимый от провайдера: стримит каждый ход либо через Anthropic API, либо через OpenAI-совместимый бэкенд в общую модель хода; кэширование промпта, инструментов и истории (TTL 1 час), компакция и старение результатов
- **`Services/OpenAIBackend.cs`** — SSE-стриминг, вызов функций и учёт токенов для любого OpenAI-совместимого эндпоинта (модель «Alt»)
- **`Services/ScriptJournal.cs` / `ExperienceStore.cs`** — слой обучения: журнал запусков кода с изменениями модели, дайджест проверенных приёмов в системный промпт, диагностический отчёт
- **`Services/HistoryStore.cs` / `MemoryStore.cs` / `ApiKeyStore.cs` / `SettingsStore.cs`** — персистентность: история диалога, память Claude, зашифрованные ключи, настройки
- **`UI/ChatPaneView.xaml`** — WPF-панель чата (виртуализированный список сообщений, markdown, кликабельные ID)
- **`Services/SelectionService.cs`** — отслеживание выделения, чтобы контекст Claude был актуальным
